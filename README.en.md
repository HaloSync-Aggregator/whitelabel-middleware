# Whitelabel Middleware

A NestJS-based middleware gateway for the PolarHub NDC API. The entire source code is **auto-generated by Claude Code agents/skills**.

## What's Included

This repository contains two things:

1. **Pre-built sample application** (`src/`) — 34 TypeScript files with 10 API endpoints, generated by the `/whitelabel-middleware-init` skill
2. **Code generation system** (`.claude/`) — 15+ Claude Code skills and references for generating and customizing the middleware

Clone this repo to get a working middleware server. Use the skill system to regenerate from scratch or customize.
- The application source is already included under `src/`
- The bundled OpenAPI reference lives under `spec/`
- Static request schema snapshots live under `docs/api-schemas/`
- Optional Claude Code workflow assets live under `.claude/`

## What This Repository Does

The middleware accepts frontend-oriented `camelCase` requests, validates them with NestJS DTOs, transforms them into the PascalCase structure expected by PolarHub, signs requests with HMAC-SHA512 when needed, and returns PolarHub responses without reshaping them.

Core rules:

- Pass-through first: transform format, not business meaning
- No hardcoded passenger/contact business data
- `transactionId` comes from the frontend and is passed through as-is
- `sender.travelAgency.contactInfoRefId` is always injected from `POLARHUB_AGENCY_CONTACT_ID`

## Prerequisites

You need valid PolarHub access credentials before real API calls will succeed:

- `POLARHUB_API_BASE_URL`
- `POLARHUB_TENANT_ID`
- `POLARHUB_API_SECRET`
- `POLARHUB_AGENCY_CONTACT_ID`

Those values are not generated by this repository. Obtain them from your PolarHub administrator, platform operator, or provisioning contact.

Without valid credentials, the server can still start locally, but outbound PolarHub API calls will fail with authentication errors.

## Quick Start

### 1. Install

```bash
git clone <your-fork-or-copy-url>
cd whitelabel-middleware-public
npm install
```

### 2. Configure Environment Variables

```bash
cp .env.example .env
```

Fill in the placeholders in `.env`:

```env
POLARHUB_API_BASE_URL=https://your-tenant.sandbox.halo-platform.net
POLARHUB_TENANT_ID=YOUR_TENANT_ID
POLARHUB_API_SECRET=your_base64_encoded_secret

POLARHUB_AGENCY_CONTACT_ID=CTC_TA1
POLARHUB_AGENCY_EMAIL=your-agency@example.com
POLARHUB_AGENCY_PHONE_COUNTRY_CODE=82
POLARHUB_AGENCY_PHONE_NUMBER=0212345678
POLARHUB_AGENCY_POSTAL_STREET=Your Street Address
POLARHUB_AGENCY_POSTAL_CODE=04534
POLARHUB_AGENCY_POSTAL_CITY=Seoul
POLARHUB_AGENCY_POSTAL_COUNTRY=KR
```

### 3. Run the Server

```bash
npm run start:dev
```

Or build and run production mode:

```bash
npm run build
npm run start:prod
```

Default local URLs:

- Swagger: `http://localhost:3000/middleware`
- Health check: `GET http://localhost:3000/middleware/health`
- API base prefix: `http://localhost:3000/middleware/polarhub`

### 4. Run with Docker

```bash
docker build -t whitelabel-middleware .
docker run -p 3000:3000 --env-file .env whitelabel-middleware
```

## Logging and Privacy

In non-production environments, request and response payloads are written to `logs/` by `src/lib/polarhub/utils/logger.ts`.

That can include sensitive data such as:

- passenger names
- contact details
- passport details
- pricing or payment-related payloads

Recommendations:

- never commit `logs/`
- avoid using development logging with real passenger data unless needed
- switch to `NODE_ENV=production` or adjust the logger before broader sharing
