# Whitelabel Middleware

A NestJS-based middleware that lets your frontend call the PolarHub API safely and conveniently — handling HMAC-SHA512 authentication and field-format transformation on the server. The entire source code is **auto-generated by Claude Code agents/skills**.

## Overview

This middleware is a **client-side gateway in front of the PolarHub API**. The complexity of airline NDC integration itself (12+ airlines with different authentication methods, request/response structures, and workflows) is abstracted by the PolarHub platform behind a single interface. This middleware only handles the boilerplate required to call that PolarHub API from a browser-based frontend:

- HMAC-SHA512 request signing — performed on the server so the secret never reaches the browser
- camelCase ↔ PascalCase mapping — converts frontend-friendly field names to the PolarHub spec
- Agency info (Sender / ContactInfo) injection — auto-populated from env vars; omitted if neither FE nor env provides it

This project uses Claude Code's agent/skill system to **auto-generate the middleware code above in minutes**.

### Why a Middleware?

The frontend (browser) cannot call the PolarHub API directly:

- **Credential protection**: HMAC secrets, Tenant IDs, and other credentials must be managed server-side only
- **Request signing**: PolarHub API requires HMAC-SHA512 signatures — doing this in the browser would expose the secret
- **Data transformation**: Converts between frontend (`camelCase`) and PolarHub (`PascalCase`) formats on the server
- **Common error format**: Wraps PolarHub error responses into a consistent HTTP response via a NestJS exception filter (airline-specific error code normalization itself is handled by PolarHub)

### Use Cases

The generated middleware is a standalone NestJS server. It can be used in several ways:

| Scenario | Description |
|:---------|:------------|
| **Standalone deploy** | Deploy as a separate server with Docker/PM2 to serve as the frontend's backend |
| **Integrate into existing server** | Absorb as a module into your OTA backend (NestJS Module import) |
| **Customize** | Add your own business logic to the generated code (mileage, discounts, payment, etc.) |
| **Learning/reference** | Use as a reference to understand NDC API integration patterns |

## Core Principles

- **Pass-through**: Transform data format only — do not modify business data
- **No hardcoding**: Do not embed passenger/contact business data in code
- **TransactionID**: Pass through the value generated and provided by the frontend as-is
- **Agency info (Sender / ContactInfo)**: Agency site code, contact details, etc. use the FE-provided value first. If not provided by FE, fall back to environment variables. If neither is set, the field is omitted from the request

## Onboarding & Credentials

To use this middleware, you need PolarHub Sandbox credentials (`POLARHUB_TENANT_ID`, `POLARHUB_API_SECRET`). These are issued through a self-serve sandbox sign-up portal — no signed contract, no sales call.

**How to onboard (self-serve):**

1. Open the sandbox sign-up portal: **https://albus.sandbox.halo-platform.net/sign-up**
2. Submit your company email, a tenant name (becomes `POLARHUB_TENANT_ID`), and an optional IATA number.
3. Sandbox credentials (`POLARHUB_TENANT_ID` + Base64 `POLARHUB_API_SECRET`) are issued within ~10 minutes.

| Credential | Description | How to get |
|---|---|---|
| `POLARHUB_TENANT_ID` | Agency / Tenant identifier | Issued by the sandbox sign-up portal |
| `POLARHUB_API_SECRET` | API secret (Base64-encoded) | Issued by the sandbox sign-up portal |
| `POLARHUB_API_BASE_URL` | Sandbox API URL | Provided with credentials |

### 30-minute fast start

1. **Sign up** — fill the portal form (~5 min); credentials are issued within ~10 min.
2. **Run the server** (~5 min) — follow [Quick Start](#quick-start) to `npm install && npm run start:dev`, then open Swagger at `http://localhost:3000/middleware`.
3. **First API call** (~20 min) — execute an `air-shopping` request against airline sandbox test data.

> Sandbox is backed by airline-provided NDC test data. Bookings created here are **not ticketed and do not affect IATA settlement**.

Learn more: [From Whitepaper to Working Code](https://halosync.kr/resources/from-whitepaper-to-working-code/)

## Quick Start

### 1. Install

```bash
git clone https://github.com/HaloSync-Aggregator/whitelabel-middleware.git
cd whitelabel-middleware
npm install
```

### 2. Configure Environment Variables

```bash
cp .env.example .env
```

Fill in the placeholders in `.env`:

```env
POLARHUB_API_BASE_URL=https://your-tenant.sandbox.halo-platform.net
POLARHUB_TENANT_ID=YOUR_TENANT_ID
POLARHUB_API_SECRET=your_base64_encoded_secret

POLARHUB_AGENCY_EMAIL=your-agency@example.com
POLARHUB_AGENCY_PHONE_COUNTRY_CODE=82
POLARHUB_AGENCY_PHONE_NUMBER=0212345678
POLARHUB_AGENCY_POSTAL_STREET=Your Street Address
POLARHUB_AGENCY_POSTAL_CODE=04534
POLARHUB_AGENCY_POSTAL_CITY=Seoul
POLARHUB_AGENCY_POSTAL_COUNTRY=KR
```

### 3. Run the Server

```bash
npm run start:dev
```

Production build:

```bash
npm run build
npm run start:prod
```

Default local URLs:

- Swagger: `http://localhost:3000/middleware`
- Health check: `GET http://localhost:3000/middleware/health`
- API base prefix: `http://localhost:3000/middleware/polarhub`

### 4. Run with Docker

```bash
docker build -t whitelabel-middleware .
docker run -p 3000:3000 --env-file .env whitelabel-middleware
```

## Environment Variables

### Required (for API calls)

| Variable | Description |
|---|---|
| `POLARHUB_API_BASE_URL` | PolarHub API base URL |
| `POLARHUB_TENANT_ID` | Tenant identifier used for auth and tenant header |
| `POLARHUB_API_SECRET` | Base64-encoded HMAC secret |

### Agency Info (Optional)

All agency-related env vars follow the **FE value first → env var fallback → omitted** principle.

**Sender fields**

| Variable | Default | Description |
|---|---|---|
| `SALES_BRANCH_ID` | unset | Site code. Ignored if FE sends `sender.travelAgency.siteCode`. Omitted if neither is set |
| `POLARHUB_AGENCY_NAME` | unset | Agency name. Ignored if FE sends `sender.travelAgency.agencyName` |
| `POLARHUB_AGENCY_CONTACT_ID` | unset | Contact info ID (e.g. `CTC_TA1`). Ignored if FE sends `sender.travelAgency.contactInfoRefId`. Also used to auto-build agency ContactInfo in OrderCreate |

**Agency contact details (auto-built for OrderCreate)**

If the FE includes agency contact in `contactInfoList`, these env vars are ignored.
If the FE omits it and `POLARHUB_AGENCY_CONTACT_ID` is set, the details below are used to auto-build the agency contact.
If neither is provided, the request is sent to PolarHub without agency contact info.

| Variable | Default | Description |
|---|---|---|
| `POLARHUB_AGENCY_EMAIL` | unset | Agency email address |
| `POLARHUB_AGENCY_PHONE_COUNTRY_CODE` | unset | Phone country dialing code |
| `POLARHUB_AGENCY_PHONE_NUMBER` | unset | Agency phone number |
| `POLARHUB_AGENCY_POSTAL_STREET` | unset | Postal street address |
| `POLARHUB_AGENCY_POSTAL_CODE` | unset | Postal code |
| `POLARHUB_AGENCY_POSTAL_CITY` | unset | City name |
| `POLARHUB_AGENCY_POSTAL_COUNTRY` | unset | Country code (e.g. `KR`) |

## Logging and Privacy

In non-production environments, request and response payloads are written to `logs/`.

Logged content may include sensitive data such as passenger names, contact details, passport info, and payment-related data.

Recommendations:

- Never commit `logs/`
- Avoid using development logging with real passenger data
- Switch to `NODE_ENV=production` before deployment
