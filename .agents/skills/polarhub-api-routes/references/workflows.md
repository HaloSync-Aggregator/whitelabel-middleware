# PolarHub Workflows Reference

The PolarHub API consists of **3 Phases** and **17 Workflows**.

## Phase 1: Prime Booking (New Reservation) - 5 Workflows

| Workflow ID | Description | API Sequence | FOP Required |
|-------------|-------------|--------------|--------------|
| `WF_PB_DEFERRED` | Deferred ticketing | AirShopping → OfferPrice → OrderCreate | - |
| `WF_PB_IMMEDIATE` | Immediate ticketing | AirShopping → OfferPrice → OrderCreate | ✅ |
| `WF_PB_SEAT` | Booking with seat | AirShopping → SeatAvailability → OfferPrice → OrderCreate | ✅ |
| `WF_PB_SERVICE` | Booking with service | AirShopping → ServiceList → OfferPrice → OrderCreate | ✅ |
| `WF_PB_SEAT_SERVICE` | Booking with seat + service | AirShopping → SeatAvailability → ServiceList → OfferPrice → OrderCreate | ✅ |

## Phase 2: Post-Booking Held (Hold Status) - 7 Workflows

| Workflow ID | Description | API Sequence | Notes |
|-------------|-------------|--------------|-------|
| `WF_HELD_SEAT` | Seat change | OrderRetrieve → SeatAvailability → OrderChange | |
| `WF_HELD_SERVICE` | Service addition | OrderRetrieve → ServiceList → OrderQuote → OrderChange | |
| `WF_HELD_CONFIRM` | Booking confirmation (ticketing) | OrderRetrieve → **[OrderQuote]** → OrderChange | ⚠️ Varies by airline |
| `WF_HELD_CANCEL` | Booking cancellation | OrderRetrieve → OrderCancel | |
| `WF_HELD_ITIN` | Itinerary change | OrderRetrieve → OrderReshop → OrderChange | |
| `WF_HELD_PAX` | Passenger info change | OrderRetrieve → OrderChange (UpdatePax) | |
| `WF_HELD_SPLIT` | PNR split | OrderRetrieve → OrderChange (UpdatePax + ReasonCode:DIV) | |

> **WF_HELD_CONFIRM Note**: Some airlines (SQ, AY, KL) require OrderQuote (RepricedOrderID).
> - **OrderQuote required**: OrderRetrieve → OrderQuote(RepricedOrderID) → OrderChange(AcceptRepricedOrder)
> - **OrderQuote not required**: OrderRetrieve → OrderChange(AcceptRepricedOrder with OrderID as OfferRefID)

## Phase 3: Post-Booking Ticketed (Post-Ticketed) - 5 Workflows

| Workflow ID | Description | API Sequence |
|-------------|-------------|--------------|
| `WF_TKT_SEAT` | Seat change | OrderRetrieve → SeatAvailability → OrderQuote → OrderChange |
| `WF_TKT_SERVICE` | Service addition | OrderRetrieve → ServiceList → OrderQuote → OrderChange |
| `WF_TKT_VOLCHANGE` | Voluntary itinerary change | OrderRetrieve → OrderReshop → OrderChange |
| `WF_TKT_REFUND` | Refund | OrderRetrieve → OrderReshop → OrderCancel |
| `WF_TKT_OCN` | Involuntary change acceptance | OrderRetrieve → OrderChange (AcceptChange) |

## Transaction ID Management (Pass-through Principle)

**CRITICAL: TransactionID is generated by FE; middleware only passes through!**

```typescript
// ✅ FE responsibility - Pre-Booking: Maintain same ID
const txnId = crypto.randomUUID().replace(/-/g, '');  // Generated by FE
AirShopping(txnId) → OfferPrice(txnId) → OrderCreate(txnId)

// ✅ FE responsibility - Post-Booking: Generate new ID and reuse
const postTxnId = crypto.randomUUID().replace(/-/g, '');  // Newly generated by FE
OrderRetrieve(postTxnId) → SeatAvailability(postTxnId) → OrderChange(postTxnId)

// ❌ Generation in middleware is prohibited
const txnId = generateTransactionId();  // Strictly prohibited!
```

## 7 Types of OrderChange

| Workflow | ChangeOrderChoice Property | Preceding API | Notes |
|----------|---------------------------|---------------|-------|
| Seat/service change | `AcceptSelectedQuotedOfferList` | SeatAvailability/ServiceList + OrderQuote | |
| Passenger info change | `UpdatePax` | - | |
| PNR split | `UpdatePax` + `ReasonCode: 'DIV'` | - | Query level |
| Involuntary change acceptance | `AcceptChange` | - | |
| Booking confirmation (deferred ticketing) | `AcceptRepricedOrder` + PaymentList | [OrderQuote] | ⚠️ Varies by airline |
| Itinerary change | `AcceptRepricedOrder` | OrderReshop | |

> **Booking confirmation (WF_HELD_CONFIRM)**: Per the OpenAPI spec examples, uses `AcceptRepricedOrder`
> - When using OrderQuote: `OfferRefID = [QuotedOffer.OfferID]`
> - When not using OrderQuote: `OfferRefID = [OrderID]`

### AcceptSelectedQuotedOfferList Example
```typescript
{
  "Query": {
    "OrderID": "...",
    "ChangeOrderChoice": {
      "AcceptSelectedQuotedOfferList": {
        "SelectedPricedOffer": [{
          "OfferID": "from_quote",
          "Owner": "SQ",
          "OfferItems": [{
            "OfferItemID": "...",
            "PaxRefID": ["PAX1"],
            "SeatSelection": { "Column": "G", "Row": "20" }
          }]
        }]
      }
    },
    "PaymentList": [...]
  }
}
```

### UpdatePax Example
```typescript
{
  "Query": {
    "OrderID": "...",
    "ChangeOrderChoice": {
      "UpdatePax": [{
        "CurrentPaxRefID": "PAX1",
        "NewPaxRefID": "PAX1"
      }]
    },
    "PaxList": [{
      "PaxID": "PAX1",
      "Individual": { "GivenName": ["NEWNAME"], "Surname": "HONG" }
    }]
  }
}
```

## Airline Workflow Support

| Tier | Airlines | Support Scope |
|------|----------|---------------|
| **Full** | AY, SQ, KL | All 17 workflows |
| **High** | AF, TK, HA | Most workflows supported |
| **Medium** | QR, EK, LH | Partial Post-Booking |
| **Basic** | AA, BA | Prime + Refund only |
| **Minimal** | TR | Prime + Hold only |
| **None** | KE | Not supported |
